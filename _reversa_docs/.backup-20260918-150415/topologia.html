Arquitetura híbrida
moderno + BaaS + offline

A mesma SPA React roda em dois modos de deployment sem mudar a interface: produção (Base44/Supabase) e offline (mock + localStorage).

Ver Code City 3D Ver grafo de módulos
Deployment

Duas variantes, um único container

A decisão fundadora D2 (SPA) + D1 (BaaS) produz uma topologia híbrida: frontend 100% cliente com o repositório de dados intercambiável via variável VITE_OFFLINE.

☁️
Modo Online (produção)

SPA consome o SDK @base44/sdk, que gerencia autenticação, CRUD e RLS no Supabase. Nenhum backend customizado existe.

UIReact 18 + Vite · Tailwind · Radix (shadcn)
↓
EstadoTanStack Query · estado de servidor
↓
Acesso@base44/sdk (base44Client.js)
↓
BaaSBase44 + Supabase · Auth · RLS · CRUD
🔌
Modo Offline (demo / dev)

Com VITE_OFFLINE=true, o SDK é trocado por um mock client que persiste no localStorage do navegador. Mesma UI, mesmos contratos, repositório diferente.

UIReact 18 + Vite · inalterada
↓
EstadoTanStack Query · inalterado
↓
AcessomockClient.js · mesmo contrato do SDK
↓
StorelocalStorage · seed via mockSeed.js
